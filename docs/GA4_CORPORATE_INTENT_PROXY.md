# GA4 における「法人意図」のプロキシと限界

汎用キーワード（例: 「コーヒーギフト」「紅茶ギフト」）は検索意図が混在しやすく、**GSC のクエリ・クリックだけでは法人としての購買意図を証明できません**。GA4 では**行動とコンバージョンのプロキシ**で仮説検証します。

## 推奨するプロキシの例

ビジネスに合わせて定義を選び、四半期ごとに見直します。

| プロキシ | 説明 | 備考 |
|----------|------|------|
| ランディングの種類 | マガジン記事（`/magazine/`） vs 商品一覧・商品詳細・特集 LP | 同一クエリでも LP によって意味が異なる |
| セッション内の遷移 | マガジン閲覧後の `/shop/`・カート・購入完了 | 既存の [`conversion-path` API](../src/app/api/ga4/conversion-path/route.ts) の考え方に近い |
| マイクロコンバージョン | 問い合わせ、資料請求、見積、まとめ買い導線のクリック | イベント設計が必要 |
| チャネル・キャンペーン | 法人向けメール・特定 UTM のセッション | 獲得チャネル別の質の比較 |

## 本リポジトリの包括レポートで分かること・分からないこと

- **分かること**: サイト全体のセッション、チャネル別・デバイス別の購入完了・売上（[`buildSiteReport`](../src/lib/buildSiteReport.ts) と同一定義）
- **分からないこと（標準 Data API のみ）**: **検索クエリ単位**の法人帰属、セッション内の複合条件に基づく厳密な帰属

マガジン配下のトラフィック（`pagePath` フィルタ）は**規模の把握**に有効ですが、「その流入が法人 CV に結びついたか」は別途探索レポートや BigQuery での結合を検討してください。

## 探索レポート（GA4 UI）での次ステップ

1. **自由形式**: ディメンション「ランディングページ」＋「セッションのデフォルト チャネル グループ」、指標「コンバージョン」「収益」
2. **ファネル**: マガジン PV → 商品 PV → 購入（イベント定義が揃っている場合）
3. **セグメント**: ランディングに `/magazine/` を含むセッション vs 含まないセッションの CV 比較

## BigQuery 連携を検討するタイミング

次のいずれかに該当する場合、エクスポートと SQL での分析を検討します。

- 検索クエリ（GSC）と GA4 の `session` を**同一粒度**で突き合わせたい
- 法人らしさを **カスタムパラメータ**（会社名入力、請求先種別など）で持ちたい
- 長期のコホート・LTV 的な議論が必要
