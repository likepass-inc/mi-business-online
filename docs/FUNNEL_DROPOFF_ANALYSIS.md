# 集客〜購入ファネル離脱分析（お中元 vs 平年）

**対象サイト**: [business.mistore.jp](https://business.mistore.jp/)

| 期間 | 日付 |
|------|------|
| お中元 | 2026-06-01 〜 2026-07-31 |
| 平年 | 2026-08-01 〜 2026-08-31 |

**データ**: GA4 Data API（`購入完了` の eventCount を購入件数とする。既存レポートと同一）。生データは [`funnel-analysis-raw.json`](funnel-analysis-raw.json)。再取得は `npx tsx scripts/analyze-purchase-funnel.ts`。

**読み方の限界**: 各ステップは **同一セッションの順序ファネルではない**。該当 `pagePath` を見たセッション数、またはイベント件数の母数比較である。カート以降はページが分岐するため、前後比は「潰れている場所」の特定に使い、厳密なステップ CVR には使わない。

可視化は Canvas（チャット横で開ける）を参照。

---

## 1. 結論 — 離脱が集中する場所

優先度の高い穴は次の 5 つ。

1. **モバイルは商品は見るがカートに入らない。** お中元の PDP→カートは desktop 47.9% に対し mobile 4.0%。カートセッションの 94% が desktop。売上も desktop が 99%。
2. **マガジン LP は集客の主戦場だが、購入にほぼ結びつかない。** 8月はマガジン LP 74,532 セッションに対し購入 36 件（CVR 0.05%）。サイト全体 CVR 0.67% の 1/14。
3. **平年のチェックアウトはカート以降で大きく細る。** カート→決済ページ（`order.aspx`）はお中元 41%・8月 13%。季節需要がなくなると「カートに入れたあと買わない」比率が上がる。
4. **購入の本体はリピーター／会員／特設 LP。** お中元の特集 LP（`/shop/o/`、中元特設含む）CVR 8.4%。会員 LP 17.3%。トップとマイページ起点の購入がマガジン記事を圧倒する。
5. **計測が三分裂している。** `購入完了` / `purchase` / `支払完了` が并存し件数が一致しない。`add_to_cart` は存在せず、`商品詳細閲覧` と `カートビュー` で代替されている。見積一時保存・用途選択・支払い種別はイベントがない。

## 3. ファネル母数（ページセッション）

セッションが各パスを一度でも見た数。

| ステップ | お中元 | 全セッション比 | 8月 | 全セッション比 |
|----------|--------|----------------|-----|----------------|
| 全セッション | 461,916 | 100% | 146,478 | 100% |
| マガジン `/magazine/` | 194,469 | 42.1% | 77,535 | 52.9% |
| 商品詳細 `/shop/g/` | 94,272 | 20.4% | 26,493 | 18.1% |
| カテゴリ `/shop/c/` | 44,330 | 9.6% | 9,129 | 6.2% |
| 特集 `/shop/o/` | 44,264 | 9.6% | 6,308 | 4.3% |
| カート `cart.aspx` | 27,789 | 6.0% | 5,142 | 3.5% |
| 注文系 `/shop/order/` | 19,747 | 4.3% | 1,795 | 1.2% |
| 購入完了（イベント） | 17,143 | 3.7% | 982 | 0.67% |

**集客側**: 8月はセッションの半分以上がマガジンを踏むが、PDP 到達は 18%。お中元でもマガジン 42% vs PDP 20%。記事閲覧と商品閲覧は別集団に近い。

**PDP→カート**: お中元 94,272 → 27,789（残 29.5%、離脱 70.5%）。8月 26,493 → 5,142（残 19.4%、離脱 80.6%）。用途プルダウン必須の UI と、モバイル非購入がここに効いている。

**カート→注文系**: お中元 27,789 → 19,747（残 71%）。8月 5,142 → 1,795（残 35%）。平年はカート投入後の離脱が季節より重い。

## 4. チェックアウト（実在 URL）

カート画面の表示順は **カート → ご依頼主情報 → お届け先と商品 → 決済・確認**。GA4 上の実パスは次のとおり。

| ページ | 役割（推定） | お中元 セッション | 8月 セッション |
|--------|----------------|-------------------|----------------|
| `/shop/cart/cart.aspx` | カート | 27,789 | 5,142 |
| `/shop/cart/goodsagree.aspx` | 規約同意・手続き開始 | 10,849 | 796 |
| `/shop/order/service.aspx` | 付帯サービス・のし | 15,935 | 1,529 |
| `/shop/order/dest.aspx` | お届け先 | 16,198 | 1,080 |
| `/shop/order/detail.aspx` | お届け先と商品の明細 | 14,845 | 1,019 |
| `/shop/order/estimate.aspx` | 見積・確認 | 14,579 | 895 |
| `/shop/order/order.aspx` | 決済・確定 | 11,410 | 670 |
| `/shop/order/save_estimate.aspx` | 見積一時保存 | 74 | 13 |

ポイント:

- `goodsagree.aspx` はカートより明らかに少ない（お中元残 39%、8月残 15.5%）。必須ステップではないか、ログイン済み会員が飛ばしている。
- お中元の `dest.aspx` は PV 123,916 / セッション 16,198（**1 セッション平均 7.7 PV**）。複数届け先の指定・やり直しが発生している。
- `estimate.aspx` はお中元で dest に近い規模。法人の「見積を出してから買う」が本線。`save_estimate.aspx` 自体は少ないが、マイページの `impsaveestimate.aspx` がお中元 805 セッションあり、保存見積の再読込は使われている。
- 8月のカート→`order.aspx` は 5,142 → 670（残 13%）。お中元は 27,789 → 11,410（残 41%）。

購入完了イベントは `order.aspx` セッションより多い（お中元 17,143 vs 11,410）。セッション内の複数注文、または完了イベントの多重発火がある。件数の解釈は §7。

## 5. デバイス — 最大の構造的離脱

### 全体

| | お中元 セッション | 購入 | CVR | 売上構成 | 8月 セッション | 購入 | CVR | 売上構成 |
|--|------------------|------|-----|----------|----------------|------|-----|----------|
| desktop | 270,808 | 16,161 | 5.97% | 99.2% | 61,767 | 552 | 0.89% | 93.2% |
| mobile | 188,931 | 966 | 0.51% | 0.8% | 81,643 | 427 | 0.52% | 6.7% |

モバイル CVR は両期間とも約 0.5%。お中元で desktop だけ 6% 近くまで上がる。季節の売上増は **desktop の法人購買** で説明できる。

### ステップ別（お中元）

| ステップ | desktop | mobile | mobile 比率 |
|----------|---------|--------|-------------|
| マガジン | 48,991 | 143,409 | 74% |
| 商品詳細 | 54,546 | 39,460 | 42% |
| カート | 26,129 | 1,585 | 6% |
| 会員エリア | 52,605 | 3,561 | 6% |

PDP→カート（同一デバイス内の母数比）:

- desktop: 54,546 → 26,129（**47.9%**）
- mobile: 39,460 → 1,585（**4.0%**）

8月も同じ形（desktop 44.2%、mobile 4.3%）。モバイルは比較・記事閲覧装置で、カート以降の UI（アドレス帳は PC 専用、届け先の複数指定、のし、請求書払い）がモバイルで成立していない。クロスデバイス（昼にスマホで見て夕方 PC で買う）は現行 GA4 では追えない。

## 6. ランディングの質

`landingPage` 起点のセッションと、その LP に紐づく `購入完了`。

| LP タイプ | お中元 セッション | 購入 | CVR | 8月 セッション | 購入 | CVR |
|-----------|-------------------|------|-----|----------------|------|-----|
| マガジン `/magazine/` | 185,613 | 161 | 0.09% | 74,532 | 36 | 0.05% |
| 商品詳細 `/shop/g/` | 38,197 | 520 | 1.36% | 10,332 | 68 | 0.66% |
| カテゴリ `/shop/c/` | 25,253 | 228 | 0.90% | 6,016 | 19 | 0.32% |
| シーン `/shop/i/` | 4,909 | 63 | 1.28% | 2,300 | 3 | 0.13% |
| 特集 `/shop/o/` | 15,846 | 1,324 | **8.36%** | 3,042 | 16 | 0.53% |
| カート | 10,709 | 316 | 2.95% | 3,351 | 36 | 1.07% |
| 会員 `/shop/customer/` | 25,820 | 4,470 | **17.3%** | 5,576 | 180 | **3.23%** |

お中元の特集 LP は `/shop/o/omochugen`（購入 842）と `/shop/o/oiochugen`（307）が中心。季節特設が商業ファネルの入口になっている。

8月の購入トップ LP は `/`（357）、`/shop/order/order.aspx`（136）、会員登録・マイページ、サイト内検索。マガジン記事で購入トップに入るのは `/magazine/article/1427` と `2345` が各 8 件。記事 2638 は 8月 LP セッション 11,174 で最多級だが、購入トップ 30 に入らない。

**含意**: マガジンは需要獲得（検索流入）には効いている。取引獲得は特設・会員・トップ・検索結果。記事→商品のクリックが計測されていないため、「記事が売っていない」のか「売っていても帰属できない」のかは GTM なしでは切り分けきれない。ただし LP 帰属の購入 36 件は、仮に帰属漏れがあってもサイト全体 982 件の過半にはなり得ない。

## 8. 会員登録

既存イベントとページ。

| | お中元 | 8月 |
|--|--------|-----|
| `新規会員登録ページ到達` | 7,642 | 2,489 |
| `authmail.aspx` セッション | 3,059 | 988 |
| `authmailcomplete.aspx` | 2,720 | 811 |
| `entry.aspx` | 2,531 | 765 |
| `register_complete` | 1,929 | 298 |
| 到達→完了 | 25.2% | 12.0% |

メール認証自体の脱落は小さい（authmail → complete は両期間とも 8 割超）。落ちるのは **本登録フォーム `entry.aspx` → `register_complete`**（お中元 76%、8月 39%）。8月は新規の完了率が季節より悪い。

`login.aspx` はお中元 1,571 / 8月 239 と少ない。実際のログイン画面は `menu.aspx`（お中元 35,375 / 8月 6,289）側に寄っている。

## 10. 仮説の判定

| 仮説 | 判定 | 根拠 |
|------|------|------|
| マガジン → PDP が最大の穴 | **部分的に成立** | マガジン LP の購入 CVR は極端に低い。ただし同一セッション遷移は未計測。記事内クリックの GTM が必要 |
| PDP → カート（用途未選択） | **成立（デバイス込み）** | PDP→カート 70–81% 減。モバイルは 96% 減。用途 UI 単体の寄与は未分離 |
| カート → 会員壁 | **二次的** | 会員 LP の購入は多い（リピーター）。新規 `register_complete` はお中元 1,929 に対し購入 17,143。大半は既存会員。新規の入口は 8月の方が詰まる |
| mobile → desktop | **最大の構造因** | カート以降は desktop 固定。クロスデバイス未計測 |
| 一時保存が見えぬ離脱 | **部分的に成立** | `estimate.aspx` はチェックアウト本線。専用保存 URL は少ない。保存ボタンのイベントがない |
| Direct 高 CV | **成立** | 8月 Direct は購入の 55%。会員・トップ・カート LP が本体 |

## 11. 次に計測すべきこと

ページパスだけで過去は見られる。足りないのは次（仕様は [`GTM_FUNNEL_TRACKING_SPEC.md`](GTM_FUNNEL_TRACKING_SPEC.md)）。

1. 記事内 `/shop/` クリック（マガジン→商品の同一セッション）
2. 用途（シーン）選択と、未選択でカートが止まる回数
3. `begin_checkout` とチェックアウトステップ（service / dest / estimate / order）
4. 見積一時保存・再読込
5. 支払い種別（カード / PortiaPAY）
6. `購入完了` と `purchase` の一本化
7. ログイン状態・企業規模（User Insight の `us_emp_range`。会社名は送らない）

新規イベントは公開後のデータからしか比較できない。過去比較はこのレポートのページパス代理指標を使う。
